What is “1 run”? — the atomic unit.  One buildable work item — a Story, Task, or Bug — taken from trigger to a merged, deployed change, including every stage and all internal retries. Anchor: 1 run ≈ 1 pull request ≈ 1 shipped change.
Higher-altitude items are NOT one run. A Feature / product requirement is a define step plus 3–15 child runs; a one-line problem statement needs elicitation first, then becomes a Feature. So the math is not “all JIRA items × per-run” — see Cost by item type below.

The upside — levers NOT priced above

Applied together, these realistically halve-to-quarter the naive bill — that gap is your safety margin.
  1. Model routing (Gateway) — premium only for hard reasoning, cheap tier for gates/triage. ~3–5× swing.
  2. Prompt / context caching — ~90%-off cached input on re-read-heavy loops. ~2–4× on input.
  3. Scoped context — feed the relevant subgraph, not the whole repo. Compounds with caching.
  4. Per-stage token budgets — hard ceiling caps runaway Coder loops (turns a $200 tail run into $30).
  5. Sovereign / self-hosted models (later) — converts variable token cost to fixed GPU cost above ~$25–30k/mo sustained.
The framing that matters: the marginal cost to ship a change is ~$3–90 + a short human review — tens of dollars for routine work. The question isn't absolute cost; it's whether that beats the engineer-hours it replaces or accelerates. For routine, well-specified changes: dramatically yes.
Caveats (they build credibility):
  • Pricing tiers are illustrative; contracted / committed-use rates and caching hit-rate move totals materially — usually down.
  • Volume is the dominant unknown; costs scale ~linearly with run throughput.
  • The Coder's token appetite varies by task/retries — Phase-0 evals replace these estimates with your real per-change numbers within weeks.
  • Human oversight (ratification/review) is a real cost not in the cloud figures — a fraction of an FTE at scale, shrinking per-change as autonomy climbs.
