Agentic SDLC · Two Ways to Build It

Local Dev-in-the-Loop  vs  Cloud Autonomous

Same brain, two bodies. One puts a developer in the driver's seat on a laptop; the other runs an autonomous pipeline in the cloud. They share a core — so you can start with one and grow into the other without rework.

System 1 · Local

Dev-in-the-Loop

The developer is the control plane. One agent on a laptop, driven interactively through spec → code → test, reviewed continuously, shipped via your existing CI.

System 2 · Cloud

Autonomous Pipeline

An orchestrator is the control plane. A fleet of ephemeral stage agents takes a ticket from spec to production autonomously, behind guardrails, with humans on the loop.

Scaled: ~$20–40k / month (pilot ~$5–8k)

🧠
They share the same core — local is a subset, not a rewrite.

The knowledge base, skills, specs, and gates are identical. Local runs them on a laptop and in your existing CI; cloud runs them on a fleet. So nothing built for one is wasted moving to the other — you add autonomy around the same core.

Crawl → Walk → Run · each tier reuses the prior tier's KB, skills, specs & gates — no rework
Recommendation: start at Crawl — cheapest, fastest, lowest-risk, and it builds the exact assets (KB, skills, specs) the cloud system needs. Move to Walk when a shared KB and centralized gates matter across the team. Invest in Run only when throughput-beyond-headcount or unattended autonomy is the explicit goal. Small ask now, big spend deferred until justified.
